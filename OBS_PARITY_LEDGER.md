# OBS behavior parity ledger

**Reviewed:** 2026-09-29  
**Scope:** Android-native equivalents for useful OBS behavior. OBS compatibility is import-only. Exporting a Stream4k project to OBS and maintaining two-way/round-trip compatibility are explicitly out of scope.

This ledger tracks the OBS feature inventory for the original REDMAGIC Astra only, with user exclusions below. “Implemented” means a code path exists; it does not mean device/runtime correctness has been proven. `:app:assembleDebug` succeeds. ADB detects the connected `NP05J` / `PQ84P01-EEA` tablet on Android 15/API 35; the app has not yet been installed/launched.

## Status key

- **Implemented, unverified:** Code path is present; runtime behavior is not yet observed.
- **Partial:** Some behavior is present; listed features or reliability work remain.
- **Missing:** No usable app path is currently implemented.
- **Android platform limit:** The desktop mechanism has no equivalent ordinary Android application API; useful user behavior may still have a documented substitute.
- **Out of scope:** The user explicitly excluded this feature; it is not an Astra readiness blocker.

## Astra hardware research and app-facing paths

REDMAGIC publicly identifies the original Astra's Snapdragon 8 Elite platform, RedCore R3 Pro, and a custom Synaptics touch chip. Its product specs disclose a 2400 × 1504 165 Hz OLED, Wi-Fi 6 / Bluetooth 5.4, Android 15, ICE-X cooling, and vendor video codec ceilings up to 4K120 encode / 8K30 encode. Qualcomm documents Oryon CPU, Adreno GPU, Hexagon NPU, Spectra ISP and other platform blocks. Those platform specifications do not prove that a particular codec/profile/rate or every Qualcomm connectivity block is exposed by Astra firmware to this app. The app must use Android runtime APIs. Sources: [REDMAGIC Astra specifications](https://global.redmagic.gg/pages/redmagic-astra-gaming-tablet-specs), [REDMAGIC Astra product page](https://global.redmagic.gg/pages/redmagic-astra-gaming-tablet), [Qualcomm Snapdragon 8 Elite platform](https://www.qualcomm.com/smartphones/products/8-series/snapdragon-8-elite-mobile-platform).

## Current user acceptance scope

- Multiple external video sources are core: independently connected UVC webcams and capture cards over USB-C, with optional audio from a capture card's USB audio interface. The Astra built-in camera is not required or offered as a new source. Each external source needs independent device/format properties, visibility, transforms and composition.
- The USB manager stores capture sessions per USB device and starts/reconfigures each visible configured source. Multiple different devices are supported in code; concurrent Astra performance, UVC compatibility and synchronization remain unverified. Assigning one physical device to two source rows is not a supported independent capture session.
- OBS project/profile/scene import is one-way. Preserve imported settings and scene-item layout where the Android app has an equivalent.
- No virtual-camera output, screen recording, AI segmentation or chroma-key development is required. An existing optional chroma-key control can remain, but is not a readiness gate.
- Editable text inputs in properties, settings, search, transforms, names, colors and filters request the Android IME when focused. This change compiles but needs a mouse-on-Astra check.

## Explicit gaps: engineering work vs Android boundaries

The word “impossible” applies to copying certain desktop operating-system mechanisms into an ordinary Android app. Most items marked partial or missing above are implementation work, not impossible work.

| Gap | Why it is a gap | What can be done on Android |
|---|---|---|
| Nested scenes/groups, ordered video/audio filter chains, independent Studio Mode, multiview/projectors, multiple audio tracks, diagnostics and recovery | Their app-native scene, DSP, UI, or lifecycle paths are incomplete. No OS rule prevents building them. | Implement the corresponding Stream4k graph and controls, then validate behavior and performance. |
| RTMPS/HLS, custom RTMP(S) at 4K120, YouTube lifecycle, recording/replay recovery, fractional frame pacing, thermal adaptation and sustained encode rates | Existing foundations lack end-to-end service/device/soak evidence and some resilience features. The connected Astra's vendor XML advertises 4K120 but reports a lower measured HEVC 4K range. | Finish protocol/container work and verify service/device combinations; performance remains hardware-dependent. |
| Full OBS profile/scene import fidelity | OBS plugins, source types, filters and schema versions vary; unsupported items/settings may only be preserved and reported. | Extend the importer/remapper from real OBS samples. Imported scene order, visibility and supported transforms already have mappings, but they remain runtime-unverified. |
| OBS-style arbitrary window/game capture using desktop hooks, DirectShow/WASAPI mechanisms | Android's normal-app sandbox does not provide those desktop hooks, global window capture, or Windows/Linux plugin/driver loading. This exact mechanism is unavailable without privileged/vendor OS integration. | Use user-approved MediaProjection for display capture; Camera2/USB Host/Android audio capture where policy and hardware permit; reimplement plugin behavior natively. These are substitutes, not the same low-level API. |
| Desktop virtual-camera driver | A normal app cannot register a system-wide virtual camera provider by itself. | Only pursue an OEM/system-provider integration if the Astra firmware exposes one; otherwise offer app-native streaming/recording output. |
| Device-specific UVC formats/controls, playback-capture policy, encoder modes, thermal/4K60 behavior | Android APIs expose capabilities, but firmware, accessory descriptors, app policy and thermal limits differ by device. | Implement capability-driven paths, then test on the real Astra and each target accessory/service. These are not universally impossible; they cannot be proven from compilation or a different device. |
| AI background segmentation using Astra silicon | Optional feature work. REDMAGIC lists Snapdragon 8 Elite and its RedCore R3 Pro gaming chip. Qualcomm documents the Snapdragon Hexagon NPU and app SDKs; REDMAGIC does not document a general-purpose third-party inference API for RedCore. Classic chroma key already runs as a compositor effect and does not need AI. | Defer it. A later AI cutout feature would use the Qualcomm inference path with a segmentation model, then need Astra latency/thermal validation. Hardware and SDK options exist, but are not integrated or required for Astra testing. |

For OBS import specifically, the intended user-visible result is one-way: import supported profile/output settings, scenes/sources/assets, canvas positions/sizes/crop/rotation/bounds, source order and visibility; report or retain unsupported data. OBS export and round-trip compatibility are not required.

## Current practical readiness

**Not ready for Astra testing.** Source-property coverage improved and the latest debug APK builds, but ordered video/audio filters, nested scenes/groups, independent Preview/Program transitions, browser audio/interaction, recording/output resilience and other P0/P1 work remain incomplete. No app runtime has been observed. Build success does not satisfy the Astra test gate.
